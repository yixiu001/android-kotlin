# 工具基础工程交互整理实施计划

**目标**：落实已确认的前六项体验改进和 Toast/弹窗规则，不扩展文本占位工具。
**技术与边界**：Kotlin、Compose，保留单 app 模块；不改账号协议、AccountEngine、Vault、测试配置和后端。当前工作区分支执行，沿用本机配置。用户已批准实施及保留数据的真机安装，无需再次确认设计。

- [x] 1. 先加入隔离 UI 回归：首页不受恢复状态打扰、恢复仍可访问、手机号粘贴和状态恢复；在旧实现验证失败。
- [x] 2. 整理账号交互：公共 Toast 结果消费，账号页内恢复弹窗、清楚的操作文案和按钮忙碌反馈；关闭能力在正式版隐藏，debug 保留诊断。
- [x] 3. 表单规范化：接受 +86/空格/连字符，不将其他国家号码或字母误转成有效手机号；错误就地展示，手机号和表单步骤可恢复，验证码不持久化。
- [x] 4. 统一反馈网页/邮箱优先级及复制邮箱兜底，两个页面共用；统一正常/本地模式产品首页接入点，不提前创建账号服务。
- [x] 5. 更新 README、当前状态、个人中心、新产品清单与本轮验收记录；运行 JVM、隔离 UI、debug 构建、lint、release 结构编译。
- [x] 6. 只用 adb install -r 覆盖安装；限定内存模拟 UI 测试，不运行存储破坏测试。核对配置及账号存储摘要，启动交付；不执行退出、注销、重置或真实短信/微信登录。

重点审查：Toast 不因旋转/回前台重放；后台启动失败不打扰本地工具且仍有重试入口；未知账号请求只恢复原操作；弹窗不会重叠；表单保存状态不会跨账号泄漏；未配置邮箱/网页不出现正式版死入口。
